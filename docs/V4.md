# V4: current development workflow

V4 separates data auditing, grouped evaluation, and model comparison. V1–V3
and their checkpoints remain historical experiment artifacts; do new work here.
The target is the **next retained post's machine-generated emotion label**.
Filtering can remove intervening posts. These labels are not independent human
ground truth or a measurement of an author's mental state.

## Files and responsibilities

| File | Responsibility |
|---|---|
| `src/emotion_schema.py` | Label names, probability columns, provenance hashes |
| `src/generate_dataset.py` | Labels plus all six labeler probabilities |
| `src/generate_embeddings.py` | Embeddings plus ordered-text/file hash manifest |
| `src/preprocess_v4.py` | Audited windows, source-row IDs and historical emotion features |
| `src/evaluation.py` | User-disjoint folds, per-user scores and clustered intervals |
| `src/train_v4.py` | Identical development folds for baselines, logistic regression and LSTM |
| `tests/test_v4.py` | Temporal, alignment, split and importer regression checks |

## Build windows

For existing local MHT artifacts, explicitly accept that the old embedding
file has no order-verification manifest. This is recorded in the data audit:

```powershell
python src/preprocess_v4.py data/interim/dataset_godknowswhat.csv data/interim/tweet_embeddings.npy data/interim/windows_v4_mht_w10.npz --allow-unverified-embeddings
```

Outputs are a compressed NPZ and a JSON audit. Existing output names are rejected.
Defaults: nine history posts, users with 20–1,000 usable posts. V4:

- drops missing text/user/time records and identical user/time/text duplicates;
- retains repeated text at different times (those may be legitimate);
- sorts by user, timestamp, then source row;
- excludes windows with timestamp ties anywhere in history or at the target;
- preserves source rows so the target's embedding never enters its own history;
- stores 391 text/time features and six historical emotion probabilities separately;
- uses an explicitly logged one-hot fallback when old CSVs lack probabilities.

Time features use UTC (naive timestamps are interpreted as UTC); without user
timezones, the hour/overnight fields do not represent local sleep schedules.
All future comparisons should use this same prepared artifact. V4 cleaning and
splits differ from V3, so their scores are not directly comparable.

To obtain actual soft historical features, generate *new* labeled/embedding
artifacts rather than overwriting the historical ones:

```powershell
python src/generate_dataset.py data/raw/cleaned_Mental-Health-Twitter.xls data/interim/dataset_mht_v4.csv
python src/generate_embeddings.py data/interim/dataset_mht_v4.csv data/interim/tweet_embeddings_mht_v4.npy
python src/preprocess_v4.py data/interim/dataset_mht_v4.csv data/interim/tweet_embeddings_mht_v4.npy data/interim/windows_v4_mht_soft_w10.npz
```

These commands require cached or downloadable Hugging Face models. Saving
probabilities does not itself remove label noise. V4 still trains against hard
target labels; soft-target loss is a separate future experiment.

## Compare on development users first

```powershell
python src/train_v4.py data/interim/windows_v4_mht_w10.npz --out runs/v4_binary_baselines --task binary
python src/train_v4.py data/interim/windows_v4_mht_w10.npz --out runs/v4_binary_lstm_emotion --task binary --models lstm --features text-time-emotion --epochs 10
python src/train_v4.py data/interim/windows_v4_mht_w10.npz --out runs/v4_binary_lstm_text --task binary --models lstm --features text-time --epochs 10
```

Default comparison models:

- **majority:** training class prior, whose argmax is the training majority;
- **persistence:** last observed emotion distribution;
- **frequency:** mean historical emotion distribution;
- **transition:** Laplace-smoothed training last-emotion → target transitions;
- **logistic:** standardized last-step and mean-history features.

The LSTM is opt-in. It uses training-only normalization, 64 LSTM units, and a
fixed epoch budget. Select epochs, class weighting and logistic `--c` through
development results. There is no test-based early stopping. `--features`
controls learned models only; historical-emotion baselines always use history.

`--task` accepts `binary`, `4cls`, `6cls`. Four-class evaluation is conditional
on targets being sadness/joy/anger/fear; it is not full six-class performance.
For four-class history, probabilities are renormalized over those four classes;
an excluded one-hot history label becomes uniform rather than an automatic
wrong prediction. Surprise remains positive in the inherited binary mapping;
that is a task convention, not a universal statement about valence.

15% of users are reserved before target filtering. Remaining users enter five
grouped folds. `--split-seed` fixes that partition; keep it fixed during tuning.
`--seed` controls model randomness and bootstrap resampling independently.
To compare training seeds, vary `--seed` only. Window-weighted scores, mean
per-user accuracy, fixed-label macro F1, per-user records and fold scores are
all saved. Binary AUC is null when the evaluated subset contains one class.

Every new run directory contains:

- `config.json`: arguments, package versions, source/data hashes and data audit;
- `splits.npz`: user assignments, validation fold, source rows and target times;
- `*_development.npz`: out-of-fold probabilities, labels, user IDs and row indices;
- `metrics.json`: scores, 95% user-cluster accuracy intervals, paired development
  accuracy differences against the baselines included in that run.

Bootstrap sampling uses whole users, preserving dependence among overlapping
windows. Intervals condition on fitted models and do not capture refit or
model-selection uncertainty. Pooled out-of-fold AUC compares predictions from
different fitted models; inspect fold AUCs too. Hard one-hot baselines can have
very poor log loss despite useful accuracy. Per-user artifacts remain local
under ignored `runs/`; use aggregate summaries when sharing results.

## Final test evaluation

After selecting and recording a configuration using development results:

```powershell
python src/train_v4.py data/interim/windows_v4_mht_w10.npz --out runs/v4_binary_final --task binary --models logistic --c 1 --evaluate-test
```

This also refits on all development users, saves test predictions/metrics and
the learned model (`model.joblib` or `model.keras`). Persisted logistic models
expect the same last-step-plus-mean feature transformation used in training.
Use only trusted joblib artifacts. There is no automatic winner selection.
Do not use repeated test runs to select hyperparameters. The original corpus
has already informed previous research; its reserved V4 users are not a new,
independent confirmation dataset. Final confirmation should use new data.

## Ingest fixes and remaining limits

Sentiment140 computes spam ratios before text deduplication. Its historical
outputs must be regenerated for that fix to affect experiments. Reddit streams
decompression into a temporary SQLite database, then selects authors and loads
only sampled histories. Temporary disk use grows with the corpus; the output
budget is approximate and can exceed the target by one author's history. The
eligible author-ID list still uses memory, but all authors' text no longer does.
Authors above the post cap are excluded rather than silently truncated.
`--max-records` limits input reading. No real Reddit corpus has been tested yet.

The older scripts remain available for reproduction; moving or deleting them
would break historical commands and document links. Historical documentation
is marked accordingly rather than silently rewritten with V4 assumptions.
